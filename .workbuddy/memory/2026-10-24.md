
## 第十九轮：主模块模拟器启动成功但 adb 端口漂移，3×180s 超时 RHT

- 产出 `doc/prompt-emulator-port-drift.md`。实例 E（MuMuPlayer-12.0-4）。
- 现象：18:25 close_emulator 正常关闭 → 18:31 Restart 到点 → launch_player 发出、窗口出现
  （`New window showing up`）→ 连续 3 次 `Emulator start timeout`（各 180s）→
  `Failed to start emulator 3 times` → RHT。
- **实测铁证**：`adb connect 16513` → 10061 拒绝；`adb connect 16512` → connected；
  netstat 只有 16512 LISTENING；用运行目录 python 跑 `EmulatorManager().all_emulator_instances`
  → `127.0.0.1:16512 | MuMuPlayer-12.0-4`。
- **MuMu 每次启动都重写 ADB 端口**：`logs/VBox.log.2`（18:25:03 结束那次）
  `NAT: Set redirect TCP 127.0.0.1:16513 -> 0.0.0.0:5555`；`VBox.log.1` 已是 16512；
  `.nemu` mtime 18:37:35（launch 18:37:22 后 13 秒）内容已变 16512。09:47 起跑时 16512 被占用顺延到 16513。
- 根因：`platform_windows.py:211-314` `emulator_start_watch()` 第 219 行把 serial 备份成局部变量，
  整个 180s 循环只 `select(serial=快照)` + `adb_connect()`（connect 的也是 `self.serial`），
  **从不重新枚举实例**。超时后 `emulator_start()` 无脑 shutdown+launch，把刚起好的虚机关掉，端口再变一次。
- 加剧因素：`find_emulator_instance()`（`platform_base.py:161-163`）`select(serial=...).count==0`
  时**直接 return None**，没有按 name 兜底 → 端口漂移后 `del_cached_property(emulator_instance)` 也救不回来，
  必须显式按 `emulator_info.name` 重新匹配。
- 修法：新增 `refresh_serial_by_name()`（按 name 匹配 `self.all_emulator_instances`），
  在 `if not devices:` 分支里 Timer(10) 节流调用，更新局部 `serial` + `self.serial` +
  `config.Emulator_Serial` 并清缓存；加 10s 进度日志。
- 现状：`config/E.json` 的 `Alas.Emulator.Serial` 已是 16512（用户或程序改过），可正常重启。

## 第二十轮：仪表盘「活动PT」停在 23 天前 —— 记录是限额检查的副产品

- 产出 `doc/prompt-dashboard-pt-not-recorded.md`。
- 证据：`config/E.json` 里 `EventGeneral.PtLimit = 0`、`Dashboard.Pt.Record = 2026-09-30 23:40:02`
  （今天 10-24，正好 23~24 天前）；webui `_update_dashboard` 在 `value_limit == ' / 0'` 时会清空尾巴，
  截图里 PT 卡片确实没有 `/xxx`，两者互相印证。
- 根因：全仓唯一写 `Dashboard.Pt` 的是 `campaign_status.py:66` `LogRes(self.config).Pt = pt`，
  而 `get_event_pt()` **唯一调用点**是 `campaign_event.py:75`（`event_pt_limit_triggered()` 内）。
  该函数开头 `if limit <= 0 or command not in tasks: return False` —— 默认 PtLimit=0 直接短路，
  连 OCR 都不做。09-30 那次是当时设过限额，活动结束被 `_disable_tasks()` 重置回 0 后再没更新。
- 影响：所有 PtLimit=0 的实例（当前 A~E 全部）。
- 修法：`CampaignStatus.update_event_pt()`（按 `Dashboard.Pt.Record` 节流 30 分钟，
  必须同时读 `config.modified`，因为 LogRes 只写 modified 不写 data）；
  `event_pt_limit_triggered()` 把 `limit<=0 or ...` 拆成两条，`limit<=0` 分支调 update_event_pt() 后返回，
  `limit>0` 分支不节流（保证及时停）。
- 临时绕过：把 PtLimit 设 999999，活动结束会被重置回 0，需重设。
- 注意：只能在 `oil_check=True`（不在自动搜索菜单）时读，此时右上角 OCR_EVENT_PT 区域可见。
