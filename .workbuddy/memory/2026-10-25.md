
## 第二十一轮：模拟器刚拉起就执行任务，nemu_ipc 与 uiautomator2 全连不上

- 产出 `doc/prompt-emulator-boot-readiness.md`。实例 E，23:00 Restart 到点。
- 现象：`launch_player` 23:00:06.179 → `Emulator start completed` 23:00:17.753（**仅 11 秒**）→
  `NemuIpcImpl init` 连试 5 次全部 `nemu_connect result=0` → `Emulator info incorrect`；
  接着 `App stop` 走 `uiautomator_2.app_stop_uiautomator2` → `http://127.0.0.1:58441/shell`
  → `RemoteDisconnected: Remote end closed connection`。
- 根因 P1：主模块 `platform_windows.py:211-314` `emulator_start_watch()` 判据只有
  adb device 状态 + `echo pong` + `list_known_packages`，**没有 sys.boot_completed**。
  MuMu 的 adb 是 vbox NAT 转发、虚机一起来端口就通，`pm list packages` 也比 boot 完成早得多。
  对照：MAA 子模块 `emulator.py:196-200` 有 `boot_completed()`，主模块漏了 → 两边不一致。
- 根因 P2：`u2` 是 `connection_attr.py:341` 的 cached_property，`connect_usb()` 会建
  `adb forward tcp:58441 -> 7912`；模拟器关闭/重启后 forward 失效且不重建。
  **全仓无任何 `del_cached_property(self,'u2')`**：`release_resource()`（connection.py:882-887）
  清了 hermit/droidcast/minitouch/maatouch/reverse_server 唯独漏 u2；
  `device.py:298` 清了 `adb` 也没清 u2。对照 nemu_ipc 那里是写了 `self.nemu_ipc_release()` 的。
- 根因 P3：`RETRY_TRIES=5`（method/utils.py:55），nemu_ipc 实测只撑约 4 秒就放弃。
- 修法：R1 watch 里加 `getprop sys.boot_completed == '1'`（未完成时返回空串不是 '0'）；
  R2 `release_resource()` 补 `del_cached_property(self,'u2')` + `emulator_check()` 成功路径也加；
  R3 nemu_ipc 重试窗口放宽到 60s+。

## 第二十二轮：MAA 插件拉起模拟器后 MaaCore 报 TouchModeNotAvailable（与上一轮同类但不同 bug）

- 产出 `doc/prompt-maa-touch-not-ready.md`。实例 alas2（16608，MuMuPlayer-15.0-7）。
- 现象：launch 00:38:11.155 → `Emulator online` 00:38:42.444（**31 秒**）→ MaaCore
  `Connected` 00:38:42.975 → 3.2 秒后 `TouchModeNotAvailable` → `StartUp` TaskChainError → RHT。
- **关键判据**：上一轮主模块实例 E 是 11 秒就判就绪（缺 boot_completed）；这次 31 秒，
  说明 MAA 插件 `MaaEmulator.wait_online()` 的 `boot_completed()` 判据**是生效的**。
  所以不是同一个 bug：`sys.boot_completed=1` 之后 Android 的 input 子系统 / MaaTouch
  服务仍需若干秒，MaaCore 3 秒内就做完触控探测，赶在前面了。
- 修法：R1 `emulator_check()` 里仅在「本次刚拉起」时用 `dumpsys input` / `service list`
  轮询 input 服务（5s 间隔、60s 上限，超时不 RHT）；
  R2 handler.py 识别 `what=='TouchModeNotAvailable'` 置标志位，`maa_start()` 遇 TaskChainError
  且标志为真时断开重连重试 2 次（每次等 10s）再 RHT。
- 附带发现（非本次原因）：日志 `游戏进程未找到：com.hypergryph.arknightt（client_type=Official）`
  —— 设备装的是 arknightt（多一个 t），Official 映射 arknights。本次因模拟器刚重启游戏确实没开，
  判据结果正确；但唤醒成功后 `game_alive()` 仍会误判 → 需用户在 MAA 设置填自定义包名。
