# 修复任务：MAA 启动辅助点错了位置（点了太阳 = 切换昼夜模式）

> 提示词使用说明：本文件全文可直接作为任务提示词交给编码代理/工程师。
> 上一份 `doc/prompt-maa-assist-missing-templates.md` 的模板缺失问题已解决（现在能跑起来了），
> 本次是**点击目标选错**，结论已定位，请按本文执行。

## 0. 硬约束（用户反复强调）

**这个功能不能写在 MAA 里**：逻辑与资源只能放在 `submodule/AlasMaaBridge/`（ALAS 侧）；
禁止放 `Maa/`、`Maa/resource/`、`Maa/cache/`；禁止改 MAA 的 `tasks.json`；
禁止使用 MaaCore（`AsstAppendTask`）实现本功能。截图与点击走 adbutils。

## 1. 现象（实例 alas2，2026-10-25 02:45 实测日志）

```
02:45:29.859 │ OPEN_ISLAND score=0.961
02:45:31.098 │ 辅助启动: skipped（未检测到灵动岛）
02:45:31.102 │ Scheduler: End task `MaaStartup`
```

`OPEN_ISLAND` 只出现一次，紧接着就是「未检测到灵动岛」，中间**没有任何** `AGREE` /
`ENTER_ASSIST` / `OPEN_SETTINGS` / `HIDE_ISLAND`，也没有 `声明页向下滚动` —— 说明这次点击
**没有任何效果**（面板没被打开）。

用户实测确认：**点击太阳图标是切换白天/夜晚模式，不是打开辅助；正确做法是点击中间那条白色圆角条（灵动岛）。**

## 2. 根因

`module/handler/assist.py` 的 `TEMPLATES` 只定义了**模板裁剪区**，`click(name)` 直接取该区域的
中心点。对 `assist_sun` 来说中心点就是**太阳图标本身** `(601, 34)`，于是点了太阳。

我之前给的坐标表里其实区分了「模板裁剪区」和「点击区域」：

| 用途 | 模板裁剪区 | 点击区域 |
|---|---|---|
| 太阳 sun | `(584,16,618,52)` | **灵动岛白色圆角条 `(572,14,706,52)`** |

但代码结构里没有"点击区域"这个字段，所以那一列被丢掉了。这是工单表述的缺陷，不是你实现的锅。

**连带副作用**：既然点到了太阳，客户端很可能已被切成**夜晚模式**。夜晚模式下灵动岛里的图标
不再是太阳，`assist_sun` 模板会失配，这正是下一轮直接走到「未检测到灵动岛」的原因
（不是逻辑 bug，是模板对不上）。

## 3. 修复步骤

### R1（必须）：sun 的模板区与点击区分离

给 `assist_sun` 一个独立的点击点，落在白色圆角条上、且避开太阳：

- 白色圆角条（灵动岛本体）：`(572, 14, 706, 52)`，中心 **(639, 33)**
- 太阳图标占位：`(584, 16, 618, 52)` —— 必须避开
- 推荐点击点：**(639, 33)**；若该点仍有副作用（见第 5 节），改用 **(660, 33)**
  （落在太阳右边缘 618 与右侧「回归」图标约 687 之间的空白段）

实现方式任选，建议：新增 `CLICK_POINTS = {'assist_sun': (639, 33)}`，
`click()` 里先看 `CLICK_POINTS`，没有再退回模板区域中心。
（`click()` 目前用 `input tap {x} {y}`，保持 adbutils 调用方式不变。）

**其余 5 个模板的点击点不用改**：`assist_agree` / `assist_enter` / `assist_hide` 的裁剪区
就是按钮本身，`assist_gear` 就是齿轮，取中心点正确。

### R2（建议）：点击后加一次校验

点击灵动岛后等待约 1 秒再截图，若出现 `assist_agree` / `assist_enter` / `assist_panel` /
`assist_hide` 任一匹配 —— 面板已打开，正常继续。
若仍只有 `assist_sun` 匹配（说明这一下没打开面板）：**不要**立刻进入 swipe 分支，
改为在 `(639,33)` 与 `(660,33)` 之间换一个点重试 1~2 次，仍失败才 warning 退出。
这样以后再出现"点错地方"能自愈，也不会把无关页面乱滑一通。

### R3（必须，用户侧）：把客户端切回白天模式

由于 R1 之前已经误点过太阳，客户端现在可能处于夜晚模式。
**请让用户手动点回白天模式**（或重新启动一次游戏确认），否则 `assist_sun` 模板失配，
修复后的代码也会直接跳过。

若用户需要在夜晚模式下也能启动辅助，则夜晚图标需要单独一张模板 —— 这属于新素材需求，
**先问用户要夜晚模式的截图，不要自己猜**，也不要把 `THRESHOLD` 调低来硬适配。

## 5. 验收（附实际输出）

1. 先把实例客户端切回**白天模式**，确认主界面顶部显示的是太阳图标。
2. 在实例打开 `MaaAssist.Enable`，跑一次 `MaaStartup`，日志期望：
   `OPEN_ISLAND score=0.9x` → （0~4 次 `声明页向下滚动`）→ `AGREE` → `ENTER_ASSIST` →
   `OPEN_SETTINGS` → `HIDE_ISLAND` → `灵动岛已隐藏，辅助设置完成`。
   **不应**再出现 `辅助启动: skipped（未检测到灵动岛）`。
3. 若点完 `(639,33)` 后日志仍停在「未检测到灵动岛」且没有打开面板，
   按 R2 换 `(660,33)` 重试，并把两次的 `score` 与结果一起贴出来。
4. 真机上若某步 `score` 在 0.7~0.85 徘徊，优先用模拟器原生 1280x720 截图重裁模板
   （素材 `doc/assist-shots/`，7 张已对齐 1280x720；`original/` 为未缩放原图），
   不要直接把阈值往下调。
