### 1.2 运行日志直接证据（运行目录 `log/2026-10-24_C.txt`，2026-10-25 01:42~01:44 的 C 扫描）

1. `01:43:12.186 [SSName] [... '特装原型', '心智单元', '心智单元', ...]` —— **心智单元II 的格子被 OCR 读成 心智单元**（II 丢失）；同页 `[SSAmount] [..., 196395, 144460, 17434, ...]`。

### 1.3 离线复现实验（已由人工执行并验证，编码 Agent 可用 R6 harness 复跑）

用 `MaterialScanner.scan_current_view()` 对 `doc/storage-shots/` 冻结截图离线回放（不连设备，`MaterialScanner.__new__` + 手工装配 `ocr_name/ocr_name_retry/ocr_amount` 即可运行，已验证可行）：

1. **污染复现**：`16_p6.png` 中 机密实验计划（非白名单，徽章实为 **960**，17_p7.png 顶行肉眼可核）被读成 **2960**；将 `AMOUNT_THRESHOLD` 从 160 提到 230 仍是 2960 —— 卡面白色画与数字同为 255 纯白，**调阈值无效**。`10_storage.png` 同理：情人节礼物(1) 读出 41/521，克洛希德科技箱读出 4456/4459/4465。
2. **污染源几何**（PIL 逐像素测量，`16_p6.png` col5 x=776, 名条顶 y=379）：数量徽章右缘固定在 **格右 x+120~123**（5 个样本格：+122/+121/+121/+120/+120），数字字距 **~13.2px**、单个数字宽 9~13px、高 20~22px，行带 **icon_top+96 ~ +120**（icon_top = 名条顶-124）。研发图纸类卡片的白色画延伸进裁剪区左侧，与首位数字的列间隙 ≤4px（列分组实测 (26,65),(69,78),(82,93)），故简单的"列投影取最右组"分不开（人工原型已试败）。
3. **截断机制**：多位数在某些滚动相位下首位被裁剪/与画粘连而丢失（2883→883、243→43、245→45）；现有 `get_records()` 的尾缀合并（短值并入长值，scanner.py:556-564）只有在**完整值也被读到**时才能纠正——单页读数无救（C 10-25 的 883）。
4. **II 尾部像素判定可行**：名条 label 区（`img[y1c+2:y1c+40, x:x+124]`）尾部 rel x∈[100,124) 的白色竖线（列内连续白 run ≥ max(8, 0.55×文字高)）计数：心智单元II = **2**，心智单元 = **0~1**（14_p4 两个行相位均验证）。II 字形实际位于 rel x≈106-119。

## 2. 根因结论（文件:行号以当前工作区为准）

| 编号 | 根因 | 证据 |
|---|---|---|
| RC1 | cnocr 丢失名条尾部 "II"，`match_whitelist()` 精确匹配（scanner.py:103-106）把 心智单元II 格判成 心智单元 | 1.2-1；1.3-4 |
| RC2 | `scan_current_view()` 页内结果用覆盖式 dict：`found[(matched, quality)] = amount`（scanner.py:391），同页两个格子匹配同名时先读的真值被后读的覆盖 | 1.2-2 |
| RC3 | 早停无确认：`_scan_pass()` 的 covered（scanner.py:508-513）按单页 found 键数计数，1 次误读即算"覆盖"，可提前触发 whitelist complete —— C 10-21 心智单元整条缺失、C 10-25 舰炮研发图SSR型只读到 1 页（883）皆由此放大 | 1.2-6；1.1 |
| RC4 | `get_records()` 多数量组循环写 dict（scanner.py:576-578）：同名同品质两个数量 → `display_name(..., suffix=True)` 生成**同一个键** `心智单元(金)`，二次写入覆盖前者，且键本身非法 | 1.2-4、1.2-5 |
| RC5 | 数量 OCR 污染：裁剪区（AMOUNT_AREA=(55,96,123,124)，scanner.py:154）左侧混入卡面白画，读出前导多余数字；阈值不可分（同 255 白） | 1.3-1、1.3-2 |
| RC6 | 数量截断：部分相位首位丢失；尾缀合并只在完整值同时被读到时有效 | 1.3-3 |
| RC7 | `QUALITY_SUFFIX`（scanner.py:29、50-51）把"同名多数量冲突"伪装成"品质变体"输出 (金)/(紫) 键 —— 白名单中**不存在**任何合法的同名异品质物品（研发图的品质已由 display_name 映射为 UR型/SSR型），该路径只会产生错误键 | 1.1、1.2-5 |

### R1 名字侧 II 判定（必须）

- 在 scanner.py 新增像素判定（建议签名 `def _has_ii_suffix(label_image) -> bool`）：对 label 区 rel x∈[100,124) 统计白色（RGB>200）列内最长连续 run，`run >= max(8, 0.55*label内文字最大列run)` 的列数 ≥2 → True。实测数据见 1.3-4。
- `scan_current_view()` 中，当 OCR 文本匹配到 `心智单元` 且 WHITELIST 存在以它为前缀的更长名（心智单元II）时，用该判定决定归属（II 在 OCR 中丢失时像素判定兜底）。泛化实现：对 WHITELIST 中所有"互为前缀"的名称对生效，不硬编码单一物品名。
- `normalize()` 现有 ‖→II 等归一保持不变。

### R2 页内不覆盖（必须）

### R3 覆盖确认（必须）
